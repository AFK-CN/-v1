# 项目调用规则

其他项目可以调用本知识库，但默认只调用已整理知识和索引，不直接读取原始数据。

## 默认入口

其他项目调用本知识库时，先读：

1. `知识库入口.md`
2. `14_KB_System/index/task_entry_index.md`
3. `14_KB_System/index/knowledge_index.json`

调用原则：先用索引定位，再按任务读取少量相关文件。禁止全盘扫库，除非用户明确要求。

## 调用范围

项目可以声明：

```yaml
use_main_kb: true
use_sub_kb:
  - 子库名称
use_methods:
  - 方法论名称
use_skills:
  - Skill 名称
avoid:
  - 不希望使用的领域或风格
```

## 默认优先级

1. 项目指定子知识库。
2. 主知识库方法论。
3. 平台知识。
4. 选题灵感库。
5. 趋势雷达。

## 默认禁止

除非你明确要求，其他项目不得调用：

- `00_Inbox/` 原始输入。
- `数据/` 原始爬虫数据。
- `99_Archive/` 低价值归档。
- `14_KB_System/assets/` 中未经审核的候选资产，除非任务明确要求审核候选。
- `decision != keep` 的资料。
- 未确认的 Skill 提案。
- 任何全库递归扫描或“随便找相关内容”的行为。

## 按需调用方式

- 内容创作：先查任务入口索引，再读取 `02_Viral_Methods/`、`03_Topic_Ideas/`、`04_Platform_Knowledge/`、`08_Content_Factory/` 中相关文件。
- 知识成长/自媒体：额外读取 `06_Sub_KB/知识成长自媒体方法论/`。
- 复盘：读取 `10_Weekly_Review/`、`09_Performance_Feedback/`、`12_User_Preferences/` 和 active Skill。
- Skill 进化：只能读取 active 和 proposals，修改必须先生成 proposal。

## 推荐项目入口文件

每个项目可创建 `KNOWLEDGE_USE.md`，说明本项目如何使用知识库。

## 长期封装方向

本知识库未来可以封装成其他项目可调用的 Skill。Skill 只作为稳定调用接口；知识库本体仍持续更新和进化。其他项目默认调用 Skill/入口/索引，不直接扫描知识库本体。
