# 李宗恒账号生产

账号 Skill 版本：1.4

使用本账号正式剧情方法和证据生产内容。复用冲突因果，不复制来源演员、人物关系、场景、品牌、故事事实或原句。

## 生产前

1. 确认内容轨道：自然短剧情、商品广告或平台项目。
2. 生成新选题时登记关系、问题、冲突角度、核心机制和流派，整批调用 `topic-memory-check --account-skill-id lizongheng`。
3. 自然短剧情从 `../METHOD_INDEX.json` 选择一个主冲突方法；需要多轮升级时再叠加递进方法。
4. 广告先建立可独立成立的正常剧情，再选择引入桥和产品角色；平台项目先确认项目壳和参与角色。
5. 写草稿前在内部确定一个主冲突、固定规则、可变槽位和结算方式；只有需要递进时才增加 M4，不用多个主冲突堆复杂度。
6. 只要交付发布标题、短文案、话题或完整发布包，必须读取 `references/publishing-copy.md`；发布层保持设定、情绪和分发入口，不强行扩写剧情总结。

## 生产

读取 `references/production.md`、`style.md`、`publishing-copy.md`、`boundaries.md` 和 `acceptance.md`。先选择一个冲突发动机，再用熟悉关系和场景建立常识，以系统迁移、控制权反转或语言重释打破常识；需要时用固定规则递进，最后用结算、关系变化或前段规则回收。写完按账号辨识度、自然对白、规则兑现、发布层协同、证据和批量差异验收。

## 生产后

1. 所有交付选题写入 `topic-memory-record`。
2. 成品写入 `production-memory-record`，登记 topic_id、content_id 和 Skill 版本 1.3。
3. 输出前执行方法消融；删除某方法后结构不变就移除该方法。

## 升级兼容

升级本账号 Skill 前必须读取 `UPGRADE_COMPATIBILITY.json` 和 `references/upgrade-compatibility.md`。旧能力 ID 不得静默丢失；替换或弃用必须经用户确认并保留回滚。整体账号升级仍只能使用本账号证据，禁止跨账号合并能力、规则、素材和正例。
