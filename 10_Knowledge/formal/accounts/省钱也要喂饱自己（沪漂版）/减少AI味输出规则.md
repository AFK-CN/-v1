# 省钱也要喂饱自己（沪漂版）减少 AI 味输出规则

账号 Skill 版本：2.1

权威来源：`skill/references/style.md`、`production.md`、`publishing-copy.md` 与 `boundaries.md`。本文件只约束本账号的一人食图文生产。

## 这个账号最容易出现的模板味

| 不要这样写 | 改成什么 |
| --- | --- |
| 每条都堆“省钱、减脂、快手、治愈” | 保持母题，只突出本条一个真实变量。 |
| 每道菜写相同页数和相同步骤 | 按操作价值分配：复杂菜详写，简单菜略写。 |
| 每道菜都用“巨好吃、绝绝子、香迷糊了” | 写菜品构成、关键动作、口感来源或真实生活附言。 |
| 为了显得专业，把每种食材都写成克和毫升 | 生活化单位为主；只有复刻确实需要时补 `g/ml`。 |
| 每篇都编一个“下班回家很累”的开头 | 只有真实素材才写生活场景；否则直接进入这顿饭。 |
| 完整餐画面直接推出营养、减脂结论 | 画面只证明餐盘构成；营养和减脂必须有独立来源。 |
| 设备旁边放成品就说“省时高效” | 展示备料、装锅、分层、设备状态和出锅过程。 |
| 报一个低价就写“人人都能这么省” | 标注日期、地区、渠道、份量和真实凭证。 |
| 每篇结尾统一“好好生活、认真吃饭” | 根据素材选择合计、知识小栏或真实碎碎念；没有就自然结束。 |
| 每篇结尾都问“你们今天吃什么？” | 没有真实互动目的就不提问；本账号自然正文不依赖固定问题收尾。 |
| 把策划、食材表、页面计划和内部说明全塞进发布文案文件 | 交付文件只留标题、正文、话题；制作信息留在内部流程。 |
| 为追求“升级感”先把账号黑桌面换成胡桃木或白桌面 | 先保持账号黑/深炭灰桌面完成食物母版；只在食物通过后按需局部换餐具。 |
| 每次生图都重新生成不同肤色、甲型和比例的手 | 每张含手图片都附带唯一手部身份锚点；固定同一女性手，只改变动作和角度，身份漂移直接重做。 |
| 连续套餐只换主菜，配菜和白米饭完全不变 | 先按完整发布包查重；2–3 个菜和主食共同变化，批次中至少安排一类非米饭主食。 |
| 不管做什么菜都固定一张步骤图 | 按复杂度分配；两道复杂菜分别拆解，简单菜只给结果，主食有操作或质感价值时再加页。 |
| 账号问题已经修过，新稿又退回“少许、炒熟即可” | 以已确认合格稿做整篇回归；主菜必须保留一人份食材、火候、时间和结束状态。 |
| 写了“蒸玉米、米饭”标题却没有任何做法 | 每个菜名和主食标题后必须有动作、执行标准或结果；空菜单段直接判失败。 |
| 正文信息不足，尾部补“红黄绿都有、看着很有食欲” | 先补完整菜谱；附言只写本餐具体动作、口感或搭配感受，不能替代正文。 |
| 用户说整篇不对，只改最后指出的碎碎念 | 回到合格基线检查整篇标题、菜单覆盖、主菜密度、配菜、主食和话题。 |
| 每页都按文字重新生成，菜一样但像不同顿饭 | 先验收食物母版，按需局部换餐具形成最终母版；封面、结果和特写从最终母版单跳派生。 |
| 把用户认可 AI 首稿、账号原图、食材特写和材质图一起喂给母版 | 食物母版只用 2–3 张账号真实完整餐；其它参考按角色后置使用。 |
| 提示词逐项写“纤维、颗粒、叶脉、壳纹、自然高光、超清锐利” | 提示词只写宏观对象、关系、动作、机位和光线；微纹理留给成图验收，不诱导模型制造假纹理。 |
| 一张完整餐同时要求米饭、青菜、肉类等所有食物都做高纹理特写 | 每餐最多两个高纹理风险单元，其余保持自然手机照片层级。 |
| 一次并行生成整批，最后才发现餐具、手和食材全漂移 | 先只做母版、风险教程、风险结果三页；校准通过后才解锁批量。 |
| 升级 Skill 时只保留最新问题对应的两条规则 | 先比较能力清单；旧能力 ID、整套多图关系和回归门必须逐项继承，显式替换要有用户确认与回滚。 |
| 只引用五页认可稿中的文案或两张锚点就说已保留整包 | 按有序回归包一次性核验母图、五页顺序、直接父关系和文件哈希；该包仍不能做真实感或生图来源。 |

## 页面怎么避免流水线感

- 第一张完整餐是菜单地图，不是为了好看而摆满无关道具。
- 无字净图是可选审美资产，不是每条必须复制的固定页。
- 复杂菜的关键动作需要教程，简单菜不为凑页数重复展示。
- 页面数跟着本餐复杂度走；不得把“封面 + 净图 + 一张固定步骤 + 两张结果”机械复制到每个发布包。
- 步骤页不能整批机械复制等分四宫格；按动作选择纵向分镜、横向分镜、主图加小步骤或错落卡片，四宫格在四张及以上教程批次中不得超过 40%。
- 周合集保持统一骨架是为了比较，菜品变量必须真实变化。
- 成本截图、订单或逐菜价格是证据，不做装饰，也不提前抢走食欲入口。
- 黑/深炭灰桌面是账号基线；可选极简黑/米白餐具只在食物母版通过后局部替换，不从材质图复制白桌面、杯子、方盘、手柄盘或摆拍构图。
- 用户认可 AI 图只做验收对照，除固定手部身份锚点外，不得作为新图生成参考。
- “实拍感”不能靠滤镜、噪点或降低清晰度伪造；先保证食材形态、锅具结构和受热状态真实。
- 教程必须发生在合理厨房过程；锅像碗、锅沿/锅柄缺失或食材与火源关系不成立时直接失败。
- 页面文件可以独立，视觉血缘不能独立：除母版外，每页直接指向母版，不允许派生自派生。

## 正文怎么保持真人感

- 按菜名自然分段，详略跟着制作难度走，不追求每段一样长。
- 复杂菜写具体动作、火候、时间和看得见的结束状态；简单菜允许一句结束。
- 保留真实生活限制和选择，例如一个人吃、工作日、设备容量、当天已有食材。
- 不虚构作者经历、口头禅、合作效果、平台结果和具体省时分钟数。
- 碎碎念、读书笔记和生活附言都不是必填项；没有来源就自然结束。
- 自然单餐默认最多一种叙事附言；碎碎念与读书笔记不合并，书、菜和情绪不强行串成散文。
- 不用空泛升华、统一问题或形容词堆叠替代菜谱、成本和过程信息。

## 发布前检查

1. 本条是否只有一个核心变量？
2. 页面详略是否由操作价值决定？
3. 价格、热量、营养、熟度、时间和效果是否都有来源？
4. 设备效率是否真的有过程证据？
5. 广告与项目证据是否污染了自然内容？
6. 去掉形容词后，读者是否仍能知道这顿饭怎么组成、怎么做或怎么选？
7. 生活附言是否来自真实素材？删除后更自然就应删除。
8. 是否已对照 `skill/references/publishing-copy-golden.md` 做整篇回归？
9. 是否运行 `skill/scripts/validate_publishing_copy.py` 并返回 `PASS`？
10. 是否准备登记 `content_id` 和当前 Skill 版本？
11. 食物母版是否只用了账号真实完整餐，并先通过食物母版门？
12. 若换餐具，是否锁定桌面、食物、构图和光线并通过材质保真门？
13. 提示词是否通过四项防火墙，并通过最终母版 + 教程 + 结果三页校准？
14. 是否已写入通过校验的 `visual-lineage.json`？
15. 是否已通过 `UPGRADE_COMPATIBILITY.json` 与五页有序回归包校验，且没有跨账号来源？
