# 省钱也要喂饱自己（沪漂版）内容生产使用说明

账号 Skill 版本：2.1

权威来源：`skill/SKILL.md`、`skill/references/production.md`、`publishing-copy.md` 与 `visual-production.md`。正式调用入口仍是 `skill/SKILL.md`。

## 第一步：先分轨

先判断自然内容、商品广告还是平台项目。广告与项目不计入自然方法证据；自然内容不能借广告素材夸大产品利益。

新选题先按 `skill/references/package-cycle.md` 形成结构化套餐计划。将规范菜品组合、主食和核心角度写入候选后，调用 `topic-memory-check --account-skill-id shengqian_weibao_hupiao` 检查历史，再运行 `skill/scripts/validate_package_batch.py` 检查同批重复；只读取少量冲突摘要。

## 第二步：只改变一个真实变量

账号母题保持“一人也要吃得完整、像样、低门槛”。每条只改变主菜、效率、成本、季节、设备或具体生活场景中的一个核心变量，不把“省钱、减脂、快手、好吃、治愈”全部堆进同一标题。

## 第三步：选择一个主结构

- 普通自然单餐：标注整餐 + 分级教程。
- 一周菜单合集：固定视觉骨架 + 七日比较索引。
- 成本透明餐：完整餐 + 必要步骤 + 真实成本凭证。
- 设备效率餐：备料 + 装锅或分层 + 设备状态 + 出锅结果。

每条只设一个主冲突和一个主结构。支持方法删除后内容没有损失，就不要叠加。

## 第四步：按操作价值分配页面

普通单餐每套先确定 2–3 个菜和 1 个主食。主食按批次轮换，不能每套都固定为白米饭；两套及以上至少包含两类主食，且不能全部是米饭类。

先交付完整餐，让读者看见这顿饭由什么组成。复杂菜需要自己的关键步骤和质感图；两道复杂菜就分别生成两张拆解页。中等菜按关键状态决定是否压成一张步骤页，简单菜只保留成品或必要动作。主食有烤制、掰开切面、颗粒或焦边价值时可增加教程/特写。不要为了版式整齐，让每道菜拥有相同页数，也不要固定五图或固定只拆一道菜。每张教程页在内部计划声明 `layout_family`；同批轮换四宫格、纵向分镜、横向分镜、主图加小步骤和错落卡片，不能把等分四宫格当默认模板。

周合集用于快速比较一周组合，不重复整套教程。成本凭证放在成品和必要步骤之后。设备效率必须由装锅、分层、状态和出锅过程证明，不能只拍设备和成品。

## 第五步：写正文

写正文前读取 `skill/references/publishing-copy.md`；自然单餐同时读取 `skill/references/publishing-copy-golden.md`，只继承结构不变量，不照抄样稿菜品、克重、时间或场景。

- 普通单餐：可用“今天吃🍽️”进入，按 emoji/菜名分段；复杂菜编号写备料、调味、火候、时间和结束状态，简单菜只保留必要动作或结果。
- 一周合集：按周一至周日列餐单索引，不展开七套教程。
- 成本餐：只有真实来源存在时才写逐菜价格和整餐合计。
- 设备餐：写清装锅或分层、温度/程序、中途状态和出锅结果。
- 商品广告：自然菜谱先成立，再用有来源的进入点承接产品；广告话术不反向定义自然语气。

勺、半碗、少许等生活化计量优先；确需提高复刻精度时补 `g/ml`。尾部根据真实素材选择整餐合计、碎碎念、知识小栏或自然结束。没有真实生活素材，不补统一升华和互动提问。

完整正文必须覆盖主菜、配菜和主食；主菜先给一人份核心食材，再写调味、火候、关键时间和肉眼可见的结束状态。任何菜名或主食标题后都不能是空段。用户指出既有合格稿时，先做整篇结构回归，不得只修最后一个局部问题。

## 第六步：做图与交付

需要配图时同时读取 `skill/references/visual-production.md`、`visual-golden.md` 和 `visual-lineage.md`。先校验黄金包 v2，再按角色选择账号原图。每个轮播页面仍是独立文件，但不得独立重生同一顿饭；用户认可 AI 图只做验收回归，不得进入生成参考。

同时读取 `skill/UPGRADE_COMPATIBILITY.json` 和 `skill/references/upgrade-compatibility.md`。五张用户认可结果必须按完整回归包一次性核验 5/5 页面、母图、页序与父关系；只看其中一两张不算已调用旧能力。兼容清单失败或出现跨账号来源时停止生产，不使用新版本登记。

先只用 2–3 张账号真实完整餐生成食物母版，账号过程图、食材特写、餐具图和用户认可 AI 图均不得参与。食物通过后，如需换餐具再做一次局部编辑并通过保真门，得到最终完整餐母版。随后只生成一张最有风险的教程和一张结果；食材形态、纹理、锅具、光线、餐具与手部都通过后才解锁其余页面。标注封面、结果、特写和配菜页直接从最终母版裁切或局部编辑；教程页直接引用最终母版、账号过程图和高风险食材真实成品图。完整发布包保存到 `美食系列/{菜名或选题名}/`，内部包含全部图片、`发布文案.txt` 和内部 `visual-lineage.json`。

桌面默认锁定账号原图的黑/深炭灰哑光表面，不再先换成胡桃木。器皿先服从账号原图；用户选择极简黑/米白套系时，使用 `optional-minimal-black-ivory-tableware-anchor.png` 只校准圆形器皿的颜色、形状和哑光材质，不带入参考图白桌面、杯子、方盘、手柄盘、灯光或构图。餐具局部编辑时，原桌面、构图、菜品、文字、箭头、人物手部与光线全部锁定。

生图提示词只描述对象、数量、动作、关系、机位、桌面与光线；“纤维、颗粒、叶脉、自然高光”等属于成图后的验收词，禁止复制进提示词，也禁止要求全画面超清锐利。同一完整餐最多安排两个高纹理风险单元。

凡页面出现手，必须同时读取并附带 `skill/assets/visual/default-hand-identity-anchor.png`。只借上半部分右上方女性手的身份特征，不复制锚点中的菜品、文字或构图。新图只允许改变动作和角度；肤色、纤长手指比例、短至中短裸粉甲型、关节轮廓和无饰品状态必须保持一致。无法附带锚点的工具不得执行手部生图。

`发布文案.txt` 只保留三个一级区块：发布标题、发布文案、话题。食材份量和做法细节应自然写进发布正文；页面计划、发布检查和内部溯源不要放进交付文件。

自然单餐交付前必须运行：

```bash
python skill/scripts/validate_publishing_copy.py --input 美食系列/{菜名或选题名}/发布文案.txt
```

返回 `FAIL` 时先修稿并重跑；返回 `PASS` 后才进入交付和生产记忆登记。

视觉包必须另外运行 `skill/scripts/validate_visual_package.py ... --write-validation`。校验会拦截用户认可 AI 图回流生成、食材特写污染食物母版、提示词防火墙失败、餐具编辑破坏食物/桌面、纯文字重生、派生自派生、高风险食材无真实参考、文件哈希漂移和逐页复核缺失；失败时不得登记完成。

## 默认发布包

内容轨道、目标人群、真实素材、标题、正文、话题、页面计划、主方法、证据和边界。内部记录主冲突、主结构、固定单元、可变槽位和证据来源。

通过发布文案与视觉包验收后执行 `topic-memory-record` 和 `production-memory-record`，登记 topic_id、content_id、账号 Skill 版本、视觉清单路径/哈希与 `visual_status=approved`。缺少任一项不算完成生产闭环。
