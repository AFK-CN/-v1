# 完整发布包查重与动态页面循环 v1.4

## 用户确认的生产口径

1. 图片由完整图文内容包驱动，查重单位应是整套发布包，而不是单张图片。
2. 每套自然一人食由 2–3 个菜加 1 个主食构成；主食不能批量全部固定为白米饭。
3. 步骤拆解页按制作复杂度与收藏价值分配；两道复杂菜可以分别获得拆解页，主食有明显操作或质感价值时也可获得教程或特写页。

## 正式证据校准

- `xhs:68cb6d6700000000120219c8`：牛肋条和基围虾分别有教程页，玉米承担主食。
- `xhs:68f9fd8d000000000700215d`：只有白灼虾获得教程页，紫米饭以颗粒特写收尾。
- `xhs:6901f2f500000000070140c5`：牛肉和开背虾分别有教程页，烤红薯另有质感特写。
- `xhs:6917060e000000000703382f`：蒜蓉虾与贝贝南瓜分别获得教程页，其余简单菜只给成品。

这些证据支持 `m03` 的既有结论：整餐先行，随后按操作价值分配页面；不支持固定五图、固定一张步骤页或固定白米饭。

## 新循环

1. 先生成套餐计划，不生成图片。
2. 为每套填写 2–3 个菜、1 个主食、核心角度、菜品复杂度与候选页面角色。
3. 形成发布包签名；先与历史生产记录查重，再对同批套餐两两查重。标题改写或页面重排不能把同一套餐变成新包。
4. 按复杂度分配页面：复杂菜给教程；中等菜视关键状态决定是否压缩为一张步骤页；简单菜只给结果。两道复杂菜就分别拆两道，主食有烤制、切面或颗粒价值时可给教程/特写。
5. 页面计划和批次验收通过后，才逐张生成独立图片。
6. 完整包交付并登记生产记忆；下一套从已登记历史继续查重。

## 查重边界

- 要拦截的是整套套餐的实质重复：相同或高度重合的菜品组合、主食和核心角度。
- 不因标题、排序、餐具、桌面或页面数量变化而判定为新发布包。
- 同一发布包内部的标注封面/无字净图、步骤/结果属于不同功能页，不做单图去重。
- 当前不新增视觉 pHash/dHash 门；除非后续出现跨发布包误用同一成图，再单独提出视觉资产查重升级。

## 执行结果

1. 账号 Skill 从 v1.3 升级至 v1.4。
2. 新增发布包计划、批内查重、主食轮换和动态步骤页规则。
3. 新增确定性批次校验脚本；包含通过与失败自测。
4. 不新增第八个方法；本次是用户生产口径与 `m03` 执行层校准。
