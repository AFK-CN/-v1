# 省钱也要喂饱自己（沪漂版）发布文案 v1.5-r2 回归修复提案

## 1. 本版取代什么

本提案取代此前只聚焦“碎碎念/读书笔记互斥”的 v1.5 初稿。初稿对问题定性不完整，不再作为待确认方案。

## 2. 回归事实

用户指定的合格基线为：

`90_Temp/美食系列/番茄豆腐一人食/发布文案.md`

它完整包含：

1. 独居一人食标题入口；
2. 主菜一人份核心食材；
3. 编号步骤中的调味、火候、时间和结束状态；
4. 配菜与主食各自可执行的短做法；
5. 基于本餐动作和口感的具体碎碎念；
6. 人群、用餐形式和真实菜品话题。

本次退化稿出现了：

- 主菜没有一人份核心食材；
- 多处使用“少许、炒熟即可”式摘要，缺少关键时间；
- 配菜信息不足；
- “蒸玉米”只有名称，没有做法；
- 碎碎念使用“红黄绿都有、看着很有食欲”等泛化表达；
- 没有 `content_id` 和 Skill 版本记录，生产闭环未完成。

## 3. 根因

正式 v1.4 已经写明复杂菜必须包含备料、调味、火候、时间和结束状态，简单菜也必须有必要动作、时间或结果。因此本次不是知识缺失，而是执行门缺失：

1. 第一条合格稿没有进入 Skill 成为可直接回归的验收基线；
2. 生产时没有强制比较合格稿与新稿的整篇结构；
3. `acceptance.md` 是人工勾选项，没有可执行脚本拦截；
4. 本次稿件未登记 `content_id` 与 Skill 版本，无法证明正式 v1.4 被完整执行；
5. 用户反馈后只修附言，未重新检查主菜、配菜、主食和话题的整篇信息密度。

## 4. 候选 Skill 修改

### 4.1 新增黄金基线

新增 `references/publishing-copy-golden.md`，只固化六类结构不变量：

- 标题入口；
- 完整菜单覆盖；
- 主菜一人份食材；
- 调味、火候、时间与结束状态；
- 配菜和主食可执行性；
- 具体而非泛化的生活附言。

明确禁止照抄番茄豆腐的菜品、克重、时间、句式或场景。

### 4.2 新增确定性校验脚本

新增 `scripts/validate_publishing_copy.py`。自然单餐交付前必须通过以下检查：

- 只有“发布标题、发布文案、话题”三个一级区块；
- 标题保留账号入口；
- 至少完整覆盖主菜、配菜和主食；
- 每个菜单标题后都有正文，不允许空段；
- 主菜包含一人份食材、三个以上编号步骤、可复刻计量、火候、关键时间和结束状态；
- 附言最多一种，拒绝已知混合标题与泛化表达；
- 话题包含账号核心人群入口。

脚本自带一正一反自测：合格结构必须通过，已知退化结构必须失败。

### 4.3 强制生产闭环

候选 `SKILL.md` 将交付顺序改为：

1. 解析正式账号 Skill；
2. 读取发布规则和黄金基线；
3. 生成完整文案；
4. 运行发布文案校验脚本；
5. 失败则修稿重跑；
6. 通过后登记 `content_id` 与 Skill 版本；
7. 最后交付。

没有通过脚本或没有生产记录的稿件，不得视为完成。
