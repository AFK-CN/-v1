# 姜胡说账号内容生产 Skill

状态：账号级正式生产入口。

触发方式：用户明确说“用姜胡说账号 Skill”“按姜胡说的知识出内容”“用姜胡说风格写选题/口播/文案/脚本”时，优先读取并执行本文件。

适用范围：只用于姜胡说账号，不是系统通用 Skill。

## 一句话总纲

姜胡说的完整内容结构不是“观点 -> 解释 -> 步骤 -> 总结”，而是：

`具体的人和事 -> 原来的处境 -> 动作与冲突 -> 转折和结果 -> 案例/模型验证 -> 抽出一个方法 -> 回到受众行动`

道理是事情发生后的解释，不是正文主体。故事和案例必须承担正文，不能只在开头出现一两句。

## 默认生产流程

1. 明确一类受众和一个具体问题。
2. 从正式方法中只选一个主因果。
3. 从正式单卡、用户真实经历或可核验公开资料中找案例；没有真实素材时不得编造朋友、经历、收入和结果。
4. 从五种正文发动机中选一种，不统一套三段论。
5. 先把事情讲清楚，再提炼一个关键判断。
6. 给出与前面案例属于同一条因果线的受众动作。
7. 自然收住，不额外升华。

## 五种正文发动机

### 1. 人物成长故事

一个人原来在做什么、卡在哪里、采取了什么动作、发生了什么意外或变化，最后怎样把经验变成方案、产品或结果。

### 2. 个人结果复盘

先给可核验结果，再倒推当时的处境、真正做对的动作、误区和代价。没有用户提供的第一手材料时，不能写成作者本人经历。

### 3. 用户追问与实操拆解

从一个真实追问进入，补前情，按顺序讲完整步骤，再用实际案例验证最容易卡住的环节。

### 4. 生活场景与多个小案例

从通勤、排队、工作、学习或交易中的具体场景进入，用两三个短案例替代抽象说教，再找共同机制。

### 5. 复杂问题与模型案例

先承认问题有难度，再建立一个最小模型，把多个真实对象放进模型解释。模型用于帮助观众看懂案例，不能代替案例。

## 正文必须讲清的内容

- 人物或事情是什么。
- 原来处在什么状态，具体卡点是什么。
- 做了哪些可看见的动作，出现了哪些物件、数字、时间或场景细节。
- 预期和实际之间有什么冲突或反差。
- 哪个动作、判断或反馈形成转折。
- 最后发生了什么，哪些部分仍不能证明。
- 这个案例真正支持哪一个核心判断。
- 普通人能复制什么、不能复制什么。

具体细节的作用是让观众看见事情。二手设备、工作记录、一次播放反馈、一篇文章、一个低价产品、通勤时间、资料包等都属于这类承重细节；只能使用正式证据或用户提供的真实材料，不能照抄来源事实，更不能虚构。

## 方法什么时候出现

- 结论不要抢在故事前面。
- 先让人物、动作、卡点、冲突和结果完成推进，再解释真正起作用的原因。
- 一个主要案例通常只提炼一个核心判断，不连续塞五六个抽象概念。
- 需要加强可信度时，可以补第二个案例，或把已经讲完的故事压缩成简单模型。
- 结构化的作用是帮助观众看懂事情，不是一开头就列三条方法。

## 利他闭环

结尾前必须回答：

1. 这件事和什么样的人有关。
2. 他今天可以先做什么。
3. 做到什么程度算完成或值得继续。
4. 最容易照抄错、做过头或误判的地方是什么。

动作必须长在前面的案例里。例如前面讲记录问题，行动就落到“记录今天被重复问的三个问题”；前面讲最小交易，行动就落到“拿一个最低版本找真实用户验证”。不能突然换成“提升认知、持续成长、马上行动”。

## 口语与防 AI 味

- 按听者自然会问的问题推进：发生了什么 -> 为什么 -> 后来怎么做 -> 结果呢 -> 那我怎么办。
- 少用抽象名词，多用人物、物件、动作、数字、场景和反馈。
- 不要每条都从“很多人……”或“很多人以为……其实……”开始。
- 不要让案例只以“比如”出现，随后进入与案例无关的课程讲义。
- 不要反复堆“价值、交付、验证、反馈、边界”等系统词。
- 不要在成品正文里出现方法 ID、source_id、知识库、证据边界、来源层级等内部字段。
- 不编造“我有个朋友”“我认识一个人”或作者亲历。
- 不用同义排比重复结论，不在结尾统一升华价值观。

## 时长规则

默认不锁三分钟。时长服从四个完成门：问题已经回答、案例或证据链已经闭环、受众行动可以执行、限制和误用已经说明。

如果用户明确要求三分钟，可把下面比例作为参考，不是机械硬门槛：

| 部分 | 参考时段 | 作用 |
|---|---:|---|
| 具体结果或冲突钩子 | 0—10 秒 | 人物、数字、事件或反常结果 |
| 故事背景 | 10—45 秒 | 人物是谁、原来处境、具体卡点 |
| 行动与转折 | 45—100 秒 | 做了什么、哪里意外、结果怎样 |
| 原因揭示 | 100—130 秒 | 真正起作用的关键因素 |
| 模型或案例验证 | 130—160 秒 | 简单模型或第二组案例 |
| 受众行动 | 160—175 秒 | 一个今天能完成的动作 |
| 自然收尾 | 175—180 秒 | 一个问题或一句判断 |

参考占比：故事、场景和案例约 50%—60%；分析和方法约 25%—30%；行动与收尾约 15%—20%。内容不完整时优先减少案例数量，不把关键环节各压成一句口号。

## 硬性失败项

出现任一项就重写：

- 开头只有抽象观点，没有具体事件、人物、结果、追问或场景。
- 观众还没进入事情，正文就开始连续教育。
- 案例没有人物、处境、动作、冲突、转折或反馈，只剩一句“比如”。
- 故事和后面的行动不在同一条因果线上。
- 讲完只能让人觉得案例厉害，却不知道自己能做什么。
- 为了统一时长删掉关键过程，或为了凑长反复解释同一个观点。
- 多条内容只替换关键词，入口、故事链、结论和行动完全相同。
- 编造作者经历、朋友、数据、收入、成交或平台反馈。

## 默认交付

输出选题、发布标题、发布文案、话题标签、黄金三秒、完整正文、互动收尾和溯源说明。内部证据与方法信息只放溯源区，不进入成品正文。

单条内容完成后按本文件“硬性失败项”自检；批量内容再读取 `批量内容验收标准.md`。
