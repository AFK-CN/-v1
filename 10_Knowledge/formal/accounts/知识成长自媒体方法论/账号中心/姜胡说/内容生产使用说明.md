# 姜胡说内容生产使用说明

统一入口：先读取并执行 `姜胡说账号内容生产Skill.md`；本文件用于补充正式方法、证据和交付细则。

用途：生产口播、长文案和批量内容时，稳定调用姜胡说已经正式入库的方法、案例结构和表达边界。故事、口语和利他闭环属于正文，不是给开头加一句场景后继续讲道理。

## 1. 固定读取顺序

1. 先明确一个目标受众和一个具体问题，不在一条内容里同时解决多个大问题。
2. 从 `METHOD_INDEX.json` 选择一个与核心因果匹配的 `approved_callable` 主方法；支持方法只有在删除后会改变结构时才保留。
3. 按方向读取正式单卡，找到可回查的内容结构、动作、转折、反馈和边界；不全扫候选区或 NAS。
4. 写作前同时读取 `减少AI味输出规则.md` 和 `内容输出标准模板.md`。
5. 商品广告、平台项目和采访合作内容先分轨，不混入自然方法频次；归属未清内容不得改写成姜胡说本人经历。

## 2. 先选正文发动机

一条内容只选一个主发动机，不能把五种结构全塞进去：

1. **人物或项目推进**：人物原处境 -> 具体动作 -> 卡点/冲突 -> 转折 -> 结果 -> 提炼一个因果。适合普通人经历、项目变化和技能变成交付。
2. **可核验结果复盘**：先给结果 -> 回到当时处境 -> 讲真正做对的动作 -> 讲误区或代价 -> 给受众可复制部分。只有用户提供第一手材料或正式证据时，才能写成第一人称。
3. **受众追问续讲**：从一个真实追问进入 -> 补上前情 -> 按顺序把步骤讲完 -> 用案例验证 -> 回答最容易卡住的环节。
4. **生活场景与案例组**：从通勤、工作、学习或交易中的具体场景进入 -> 连续给两三个短案例 -> 找共同机制 -> 给一个低门槛动作。
5. **复杂问题与模型案例**：先承认问题难点 -> 建立最小模型 -> 把真实对象放进模型逐项解释 -> 得出判断 -> 告诉受众如何用模型检查自己的问题。

## 3. 姜胡说式正文顺序

- 常用主链：`具体的人/事/结果 -> 原来的处境 -> 做了什么 -> 遇到什么卡点 -> 哪里发生转折 -> 得到什么反馈 -> 只提炼一个关键判断 -> 受众下一步怎么做`。
- 故事型内容里，案例是正文主干，不是黄金三秒后的装饰。人物、动作、冲突和结果没有讲清楚前，不急着上方法论。
- 每讲完一个案例，只抽一个与案例直接相关的因果；不要连续堆三个概念证明深度。
- 口语化按听者的疑问推进：他说到这里，听者会问“然后呢”“为什么”“那普通人怎么办”，下一句就回答这个问题。
- 结尾自然停在一个动作、判断或待验证问题上，不再额外升华价值观。

## 4. 利他闭环

内容完成前必须替受众回答四件事：

1. 这件事和什么样的人有关。
2. 他今天最先能做的动作是什么。
3. 做到什么程度算完成或值得继续。
4. 最容易照抄错、做过头或误判的地方是什么。

故事讲得再完整，如果受众只能感叹“这个人真厉害”，仍然不算完成。必须把案例中的机制翻译成受众可执行的一步，但不能把单例说成普遍规律。

## 5. 时长与展开尺度

- 不预设所有内容必须三分钟。时长由具体问题、案例链、解释和行动闭环是否完整决定。
- 用户限定时长时，优先减少案例数量或只保留一个主因果，不把每个环节压成一句口号。
- 没有限定时长时，讲到“问题已回答、案例已闭环、行动能执行、边界已说明”就停；不为凑长增加同义观点。
- 同一批内容允许长短不同。人物故事、结果复盘和复杂模型通常需要更多铺垫；单一操作问题可以更短。

## 6. 证据与真实性

- 正式案例入口：人物/项目推进可参考 `douyin:7628990469552229683`；结果复盘参考 `douyin:7632345202723769627`；受众追问续讲参考 `douyin:7647562491416939791`；场景案例组参考 `douyin:7546226278702058779`；模型案例参考 `douyin:6813708566600404236`；行动验证参考 `douyin:7515401408406293779`。
- 只复用问题—动作—冲突—反馈的结构和已验证方法，不复制来源人物身份、故事事实、原句或外部结果。
- 没有真实案例时，可以明确写“假设有这样一个场景”，但不能假装是“我有个朋友”“我认识一个人”或作者亲历。
- 证据字段、source_id、方法 ID 和内部审核说明放在发布包的溯源区，不进入口播正文。

## 7. 输出前总检

1. 开头是否已经落到一个人、一件事、一个结果、一个追问或一个生活场景。
2. 正文是否真的发生了动作、卡点、转折或反馈，而不是只有观点换说法。
3. 抽象判断是否晚于证据，且一段只推进一个因果。
4. 受众是否知道今天做什么、做到什么算完成、哪里容易做错。
5. 时长是否来自内容完整度，而不是机械对齐同一字数。
6. 是否编造第一人称经历、朋友故事、数据、收入或效果。
7. 是否误用归属未清内容，或把单条案例写成稳定规律。
