# 小红书爆款方法论 v1

## 方法 1：一周计划型收藏内容

```yaml
method_id: xhs-method-001
platform: xhs
适用领域: 美食、减脂、备餐、生活方式
适用人群: 独居、上班族、减脂人群、想省事的人
适用场景: 用户想直接照着做，不想重新规划
核心机制: 把复杂决策压缩成一周清单，提高收藏和转发价值
内容结构: 场景承诺 -> 周一到周日安排 -> 每天具体搭配 -> 标签覆盖需求
标题结构: 一周 + 不重样/合集/指南 + 明确收益
可复用模板: 一周不重样{目标}来啦：周1...周7...，适合{人群}直接照着吃/做/练
证据案例: note_id=69fdc6340000000035021c5e, note_id=6a1ee0840000000035025a38
指标表现: 3975赞/1925藏/738分享；3517赞/1355藏/528分享
```

使用判断：

- 适合做收藏型小红书。
- 必须给足细节，不能只写概念。
- 最好让用户“一眼知道收藏后能照着做”。

## 方法 2：身份场景代入

```yaml
method_id: xhs-method-002
platform: xhs
适用领域: 美食、生活、效率、自律
适用人群: 独居、上班族、新手、减脂期用户
适用场景: 用户需要看到“这就是我的生活”
核心机制: 用身份标签降低距离感，再给出具体方案
内容结构: 身份场景 -> 具体问题 -> 可执行方案 -> 真实生活感
标题结构: 独居一人食 / 上班族 / 新手 + 具体收益
可复用模板: {身份}|{场景}这样做，{结果/感受}
证据案例: note_id=6a15733e000000003501d23d, note_id=69f719750000000035025f43
指标表现: 2891赞/1014藏；1771赞/810藏
```

使用判断：

- 小红书不只卖方法，也卖生活代入。
- 标题里的人群和场景要具体，避免“所有人都适用”。

## 方法 3：步骤 + 量化细节

```yaml
method_id: xhs-method-003
platform: xhs
适用领域: 菜谱、健身、学习、工具教程
适用人群: 新手、怕麻烦的人、需要照抄的人
适用场景: 用户愿意收藏但担心执行难
核心机制: 用步骤、克数、热量、时间等细节降低执行成本
内容结构: 结果图/承诺 -> 材料或清单 -> 1/2/3 步骤 -> 注意点
标题结构: 超简单 / 附步骤 / 附清单 / 从买到存
可复用模板: {主题}指南：从{起点}到{终点}，附{清单/步骤/模板}
证据案例: note_id=6954faae000000001e002da4, note_id=6a15733e000000003501d23d
指标表现: 备餐指南 1240赞/1104藏/68评论；单餐步骤 2891赞/1014藏
```

使用判断：

- 收藏高的内容通常给了可复用结构。
- 如果内容是知识类，也可以改成“步骤 + 模板 + 案例”。

## 方法 4：评论区问题征集

```yaml
method_id: xhs-method-004
platform: xhs
适用领域: 美食、知识、教程、经验分享
适用人群: 有具体卡点的人
适用场景: 需要制造互动并收集下一批选题
核心机制: 把评论区变成需求池
内容结构: 先给一个完整指南 -> 问用户最卡的问题 -> 后续逐条回应
标题结构: 指南 / 菜单 / 模板 + 评论区提问
证据案例: note_id=6954faae000000001e002da4
指标表现: 68评论，为小红书样本最高评论
```

使用判断：

- 适合用于知识库持续进化。
- 评论要被回收进 `09_Performance_Feedback/` 或后续 JSON，否则互动价值会浪费。
