# 项目已解决问题与修复方式

状态：approved  
用途：沉淀历史会话中反复出现、已解决、未来应避免重复踩坑的问题。

## 1. 大索引被默认读取

问题：`knowledge_index.json` 过大，容易被误当成人和 Codex 默认入口。  
原因：全量机器索引和默认读取入口混在一起。  
修复：默认入口改为轻量摘要、任务入口和账号索引；全量索引只给脚本、全量审计或明确要求。  
后续规则：新增索引或重构索引时，必须同步更新入口文档、路由、验证器和测试。

## 2. blocked 边界缺失或过度展开

问题：原始资料、归档和 inbox 边界容易在索引中缺失，或被展开成大量原始文件。  
原因：生成逻辑依赖目录是否存在，且没有把 blocked 边界当作固定契约。  
修复：`raw_blocked_index.json` 固定表达 blocked 边界，只记录目录级规则和 exists 状态。  
后续规则：默认禁止读 `数据/`、`00_Inbox/`、`99_Archive/`、`80_Local/`、`20_User/private/`、runtime。

## 3. 账号模板被误放到方向层

问题：内容输出模板、减少 AI 味规则曾被放进单个方向，导致跨方向复用困难。  
原因：从当前方向推断模板归属，而不是从账号级工作流判断。  
修复：账号通用内容生产说明、减少 AI 味规则、内容输出标准模板放到账号中心。  
后续规则：方向目录放方法论和材料；跨方向生成标准默认放账号层。

## 4. 旧 handoff 状态覆盖当前正式状态

问题：旧交接文档中的 candidate/pending wording 会误导后续会话。  
原因：规划文档滞后于正式目录、审计结果和索引输出。  
修复：正式状态以当前目录、审计 register、验证脚本、索引和测试为准。  
后续规则：正式入库后要清理 stale 状态词，但保留“候选金句”等证据边界术语。

## 5. 粗扫范围靠人工判断

问题：容易让 Codex 手动扫原始数据，或者误把单个排行榜当成完整库存。  
原因：缺少 profile 化粗扫引擎和验证报告。  
修复：用 `tools/content_rough_scan.py`、profile 配置、inventory、validation report 和 overrides 做机器识别与异常审核。  
后续规则：先看代码产物和验证报告；没有产物就明确说没有，不要推断覆盖。

## 6. 长任务状态不可观测

问题：后台下载/学习任务只给 PID，后续难判断是否健康。  
原因：缺少状态文件、心跳、日志和 manifest 联合验证。  
修复：长任务写 `.status.json`、heartbeat、日志、队列状态和 manifest。  
后续规则：优先用状态文件、日志增长、manifest 和队列计数判断；不要只依赖 `ps`。

## 7. 目录物理迁移后旧路径残留

问题：旧目录和新目录并存、配置重复、绝对路径写死，会影响迁移和分享。  
原因：系统层、运行态、用户层和知识层边界没有物理收口。  
修复：系统规则/配置/Skill/路由迁到 `00_System/shareable/`，运行态留在 `00_System/runtime/`，知识索引迁到 `10_Knowledge/evidence/index/`。  
后续规则：迁移后必须重建索引和 Skill 包，跑测试、`validate-system`、旧路径搜索、pyc 清理。

## 8. 记忆候选被每次结束机械生成

问题：如果每次结束都生成记忆，会产生大量低价值候选。  
原因：自动记忆缺少阈值和跳过规则。  
修复：`memory --evaluate-text` 先评分，只有达到阈值才写 runtime pending。  
后续规则：普通结束语、一次性过程、临时方案和用户明确说不用记的内容不生成候选。
