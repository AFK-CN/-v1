# 姜胡说减少 AI 味输出规则

账号 Skill 版本：1.4

权威来源：`skill/references/style.md`、`production.md`、`publishing-copy.md` 与 `boundaries.md`。本文件不是通用口语化清单，只约束姜胡说账号生产。

## 先判断有没有写成“讲义”

姜胡说式内容可以讲道理，但道理不能独占正文。每个关键判断前后，至少要有一个具体人物、场景、动作、卡点、反馈、案例变量或模型关系托住。如果删掉所有观点后，观众完全不知道发生了什么，这篇内容就太像 AI 讲义。

## 常见 AI 腔替换

| 不要这样写 | 改成什么 |
| --- | --- |
| “很多人都不知道……” | 有来源就说问题来自哪条评论或哪次交流；没来源就直接进入场景。 |
| “本质上、归根结底……”开场 | 先还原人、事、动作和结果；模型题也要马上给变量验证。 |
| 连续“第一、第二、第三” | 改成真实行动顺序、追问顺序或因果推进。 |
| 每段都用“这说明……” | 全文只保留一个关键判断，其余让案例和结果自己成立。 |
| “在这个时代，普通人一定要……” | 写清是哪条规则、哪种资源或哪个现实约束变了。 |
| “只要……就能……” | 补适用条件、验证方式和不成立的情况。 |
| “希望对你有帮助” | 给第一步、完成标准、自检问题或判停条件。 |

## 口语不是加语气词

- 按一个真实听众的追问来讲：到底发生了什么？为什么会这样？后来怎么处理？我能怎么判断？
- 叙事句可以长一点，把动作和过程说清；短句只用来转折和落点，不把全文切成同样长度。
- 可以保留自然补充和轻微自我修正，但不故意加“你知道吗”“重点来了”“说白了”等口头禅。
- 不照搬直播暖场、反复招呼、设备调试和临场填充。

## 故事和案例怎么避免假

- 没有真实第一人称材料，不写“我有个朋友”“我去年赚了”“很多粉丝问我”。
- 假设案例必须明示是例子，不能伪装成账号本人经历。
- 案例至少包含处境、动作和结果或反馈；只换人物名字、行业和金额不是新案例。
- 结果没有证据时降低结论强度，不用具体数字制造可信感。

## 利他不是最后加一句鼓励

利他要在正文里解决一个具体判断：观众如何识别自己属于哪种情况、先做什么、观察什么、做到什么算完成、什么时候不要继续。知识点再多，如果观众听完仍不知道怎么判断，就不算完成。

## 发布前朗读检查

1. 有没有一句现实中不会对人这样说、只能写在报告里的话？
2. 前 20% 是否已经出现人、事、问题、结果或关键变量？
3. 每个抽象判断是否有案例、动作、反馈或关系支撑？
4. 有没有三段在换词重复同一个结论？
5. 结尾是否给了可用判断或下一步，而不是空泛升华？
6. 是否编造了第一人称、评论、数字或外部结果？
