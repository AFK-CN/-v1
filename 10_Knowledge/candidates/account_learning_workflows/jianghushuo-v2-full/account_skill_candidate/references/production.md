# 生产机制

## 选择顺序

1. 先明确受众正在处理的一个具体问题。
2. 从正式方法中只选一个主方法，再选择一个正文发动机。
3. 写清固定单元和可变槽位；固定单元不完整时不开始写正文。
4. 根据主方法决定观点进入时机：案例型内容先推进过程；模型型内容可以先给判断，但必须立即进入案例、变量或关系验证，并在结尾回到受众判断、行动和边界。

## 正式方法到正文发动机

| 主方法 | 优先正文发动机 | 必须保留的区别 |
| --- | --- | --- |
| 用持续有用内容建立关系与分发杠杆 | 受众追问续讲、可核验结果复盘 | 区分平台随机流量与用户主动复访；内容必须先提供真实价值 |
| 把真实经历与解决过程转成信任资产 | 人物或项目推进、可核验结果复盘 | 真实处境、过程、变化和可回查帮助共同形成信任，不能只讲“真诚” |
| 让输入通过输出和使用发生转化 | 人物或项目推进、复杂问题与模型案例 | 输入必须经过输出、使用或反馈才算转化，不把收藏和摘抄当结果 |
| 用生活细节和真实问题承载抽象表达 | 生活场景与案例组 | 先让观众看见动作、选择或后果，再提炼判断 |
| 从规则变化和资源重组中识别机会 | 复杂问题与模型案例、生活场景与案例组 | 讲清规则、资源和位置如何改变选择，不把“抓风口”当答案 |
| 从真实问题到最小产品再到反馈修正 | 人物或项目推进、可核验结果复盘 | 问题、最小交付、真实使用和增删转向必须形成反馈闭环 |
| 把重复解决过程记录并封装成复利资产 | 人物或项目推进、可核验结果复盘 | 从重复问题到记录、封装、复用和复利，不把一次成品直接称为资产 |
| 把长期目标改写成每天可交付的小过程 | 人物或项目推进 | 小动作、完成标准、连续反馈和长期目标之间要能对应 |
| 用关键概念和结构模型压缩复杂问题 | 复杂问题与模型案例 | 模型必须改变对案例的解释或行动，允许多章节展开 |
| 用可验证价值交换重构赚钱判断 | 生活场景与案例组、复杂问题与模型案例 | 收入判断回到对谁提供什么可验证价值，不用身份和愿望替代交换 |

## 五种正文发动机

### 1. 人物或项目推进

- 适用：人物正在做一件事，过程中的行动、阻力和反馈比结论更重要。
- 固定单元：原处境 -> 具体行动 -> 阻力或失败 -> 调整/转折 -> 可观察反馈 -> 一个判断 -> 受众下一步。
- 可变槽位：人物身份、项目类型、约束、行动轮次、反馈形式。
- 完成门：删除观点后仍能看懂发生了什么；观点能由过程自然推出。

### 2. 可核验结果复盘

- 适用：已有结果、前后变化、用户反馈或可回查产出。
- 固定单元：先给结果 -> 交代起点和约束 -> 还原关键动作 -> 说明卡点与修正 -> 给证据和未解决部分 -> 提炼可迁移判断。
- 可变槽位：结果类型、周期、参与者、验证方式和失败部分。
- 完成门：结果、动作和因果能对应；没有把相关性写成必然性。

### 3. 受众追问续讲

- 适用：上一条内容、评论或真实交流留下一个具体追问或误解。
- 固定单元：复述具体问题 -> 指出误解发生在哪 -> 用新案例展开 -> 比较错误做法 -> 给第一步和边界 -> 留下自然的下一问。
- 可变槽位：问题来源、案例、对比对象、受众行动。
- 完成门：新内容独立可看；不是把上一条观点换句话再说。

### 4. 生活场景与案例组

- 适用：抽象问题需要通过多个日常场景帮助观众对号入座。
- 固定单元：具体场景进入 -> 人物动作和后果 -> 第二场景对照或递进 -> 找共同机制 -> 回到受众选择。
- 可变槽位：关系、地点、动作、案例数量和对比方式。
- 完成门：每个案例都增加新证据或新边界；不能只是同一结论的三次改写。

### 5. 复杂问题与模型案例

- 适用：问题涉及多变量、规则变化、资源关系或需要结构模型压缩。
- 固定单元：先给具体问题 -> 摆出两个以上案例/变量 -> 找关键关系 -> 给最小模型 -> 用模型重新解释案例 -> 给可验证动作和失效边界。
- 可变槽位：模型形式、案例数量、变量、应用场景。
- 完成门：模型能产生一个新判断或行动；没有用图表和术语包装常识。

## 共用机制

- 张力：来自“行动还没完成、结果尚未验证、追问尚未回答或模型尚未解释完”，不靠连续悬念词。
- 信任：来自真实问题、具体动作、卡点、修正、结果和未解决部分；没有证据时降低结论强度。
- 理解：案例型内容由过程推出判断；模型型内容使用“判断 -> 案例/变量 -> 模型关系 -> 回看案例 -> 应用或验证”循环。一段只推进一层因果，观点不能脱离证据连续讲义化。
- 受益：结尾至少交付一种可使用结果——判断标准、自检问题或第一步行动；行动型内容还需给完成标准或判停条件。
- 篇幅：由问题、案例链、解释、行动和边界是否完成决定，不锁统一时长；缺一项就补证据，不用重复观点凑长。

## 篇幅路由

- 单一判断、小步行动或生活案例：完成一个“问题—案例/动作—判断—受众落点”闭环即可，不为显得深度增加第二套道理。
- 项目、结果复盘或产品反馈：把起点、关键动作、卡点、修正和结果讲完整；篇幅随真实过程增加。
- 结构模型和复杂机会判断：允许使用多个章节，每章完成一次“问题/判断—案例—模型关系—应用”循环，并在章节间做短回收。不能因为短视频时长预设而删掉关键变量，也不能照搬直播暖场和重复口头确认。

## 默认交付

选题、发布标题、发布文案、话题标签、黄金三秒、完整正文、互动收尾和内部溯源。内部额外记录主方法、正文发动机、固定单元、可变槽位和完成门；这些字段不进入发布正文。
