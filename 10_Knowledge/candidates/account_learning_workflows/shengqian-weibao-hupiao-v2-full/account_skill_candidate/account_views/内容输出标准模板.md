# 省钱也要喂饱自己（沪漂版）内容输出标准模板

账号 Skill 版本：2.1

权威来源：`skill/references/production.md` 与七个正式方法。每条只选一个主模板；固定母题保持稳定，可变槽位来自本次真实餐食和素材。

## 模板一：普通自然单餐

```text
本条唯一变量：【主菜/季节/场景/效率中的一个】
目标读者：【独居/沪漂/打工人 + 具体用餐场景】
套餐构成：【菜 1】【菜 2】【可选菜 3】+【主食；批次中轮换，不固定白米饭】
发布包签名：【规范菜品组合 + 主食类别 + 核心角度】

页面 1：标注完整餐——主食、主菜、配菜、汤饮或水果的真实构成。
页面 2：可选无字净图——只有素材确实成立时保留。
页面 3 起：复杂菜关键步骤——一道复杂菜至少一张，两道复杂菜分别拆解；主食有操作/质感价值时可加教程或特写。教程页为内部计划声明 `layout_family`，同批轮换四宫格、纵排、横向分镜、主图加小步骤或错落卡片。
简单菜：只给必要动作或成品，不重复教程。
默认视觉：账号原图的黑/深炭灰哑光桌面 + 手机直闪家常摆放；餐具先服从账号原图，可选极简黑/米白圆形哑光器皿只做后置局部替换。

黄金参考：2–3 张账号真实完整餐独占食物母版生成；账号过程/结果图只负责厨房过程与高风险食材；用户认可 AI 首稿只做整包连续性验收。高风险食材必须计划 `ingredient_real` 参考。

升级兼容：调用 `skill/UPGRADE_COMPATIBILITY.json`；用户认可五页结果以有序回归包校验 5/5 页面、无字母图、页序和直接父关系。回归包不进入食物母版或生图输入。

视觉血缘：先生成并验收食物母版；如需换餐具，只在食物通过后局部编辑，并锁定桌面、食物、构图和光线，形成最终母版。标注封面、结果、特写和配菜直接从最终母版裁切/局部编辑。教程引用最终母版 + 账号过程图 + 高风险食材真实图。最终母版、风险教程、风险结果三页校准后再解锁其余页面。

提示词防火墙：不把验收清单复制进生图提示词，不枚举纤维、颗粒、叶脉等微纹理，不要求全画面统一锐利；同一完整餐最多两个 `texture_risk=high` 单元。

固定手部：只要出现手，必须附带 Skill 内唯一手部身份锚点；固定同一女性、纤长自然手指、短至中短半透明裸粉甲、偏白暖肤色、无饰品。只改变动作，不得随机换手。

正文：
【emoji + 菜名】
【一人份真实食材；需要时用生活化单位 + g/ml】
1. 必要备料或预处理
2. 调味比例、火候与关键时间
3. 可见结束状态或真实口感来源

【简单菜名】只写必要动作、时间或结果，不允许只留菜名
【主食】写数量与必要做法、时间或结果，不允许空段
尾部：【自然结束/真实碎碎念/有来源的读书笔记三选一；其它证据模块按素材选择】
话题：【人群 + 场景 + 实际菜名；不补未证明效果】
```

完成门：历史与同批发布包查重通过；每套为 2–3 个菜加 1 个变化主食；完整餐先成立，教程详略由操作价值决定且页数不固定；克重、调味、时间和温度与真实执行一致；已对照 `skill/references/publishing-copy-golden.md` 完成整篇回归；`skill/scripts/validate_publishing_copy.py` 返回 `PASS`；没有真实附言时不强行收尾。

## 模板二：一周菜单合集

```text
周主题：【一周减脂餐/工作日晚餐/季节菜单等一个母题】

封面：七日完整餐缩略或统一菜单地图。
周一：一张完整餐 + 菜名构成。
周二至周日：保持相同视觉骨架，只更换真实菜品变量。

正文：提供七日索引、必要替换建议和真实限制。
不重复每道菜完整教程；需要教程时链接或另做单餐内容。
没有真实周末语境、阶段变化或菜单说明时，索引后直接进入话题。
```

完成门：内容价值是快速比较一周组合，不是假装七篇单餐教程拼在一起。

## 模板三：成本透明餐

```text
本餐场景：【日期 + 地区 + 渠道 + 份量】

页面 1：完整餐成品。
页面 2 起：真正影响复现的关键步骤。
尾页：逐菜价格、整餐合计或真实订单截图。

正文：
菜品构成 -> 必要做法 -> 每项价格来源 -> 整餐合计 -> 价格边界
```

完成门：价格有日期、地区、渠道和份量，不承诺长期低价。

## 模板四：设备效率餐

```text
设备与真实任务：【设备容量 + 同时完成哪些食物】

页面 1：完整餐结果。
页面 2：备料和摆放逻辑。
页面 3：装锅、分层或并行安排。
页面 4：设备运行状态或中途节点。
页面 5：出锅后的单菜结果和整餐组合。

正文：为什么这样分层 -> 各食物关键动作 -> 状态观察 -> 真实限制
```

完成门：效率由过程证明；没有来源不写具体省时分钟数、熟度或食品安全结论。

## 商品广告附加模板

```text
广告前自然内容：拿掉产品仍能成立的餐食任务。
产品进入点：在哪个真实制作或选择节点出现？
产品角色：解决什么具体问题？
商业证据：卖点、价格和购买利益来自哪里？
广告后收束：回到餐食结果、步骤或生活场景。
```

## 统一发布包

- 内容轨道与本条唯一变量。
- 标题：稳定母题 + 一个具体变化。
- 页面计划：每页承担一个操作或比较价值。
- 正文：按菜名分段，复杂菜详写、简单菜略写。
- 话题：服务检索，不补造功效。
- 内部证据：素材页、价格来源、商业属性、主结构和边界。
- 保存目录：`美食系列/{菜名或选题名}/`。
- 文件组成：按序号命名的全部独立图片 + `发布文案.txt`；不得同时保留 `发布文案.md`。
- 内部视觉清单：`visual-lineage.json`，记录黄金参考、父资产、生成模式、提示词/文件哈希、生成器版本、三页校准和逐页视觉复核。
- `发布文案.txt` 固定只含：`# 发布标题`、`# 发布文案`、`# 话题`。
- 食材表、页面计划、发布检查、执行口径和内部溯源不得写入 `发布文案.txt`。
- 可选餐具材质锚点：`skill/assets/visual/optional-minimal-black-ivory-tableware-anchor.png`，只在食物母版通过后用于器皿局部替换；旧胡桃木锚点仅供回滚。
- 内部套餐计划与批次校验：按 `skill/references/package-cycle.md` 记录规范菜品、主食、复杂度、页面角色和教程 `layout_family`，并运行 `skill/scripts/validate_package_batch.py`；该计划不进入 `发布文案.txt`。
- 自然单餐文案回归：读取 `skill/references/publishing-copy-golden.md`，运行 `skill/scripts/validate_publishing_copy.py --input <发布文案.txt>`；失败时禁止交付。
- 视觉校验：运行 `skill/scripts/validate_visual_golden.py` 与 `skill/scripts/validate_visual_package.py ... --write-validation`；未通过不得交付。
- 生产闭环：验收通过后登记 `content_id`、当前账号 Skill 版本、视觉清单路径/哈希和 `visual_status=approved`；缺少任一项不视为完成。
