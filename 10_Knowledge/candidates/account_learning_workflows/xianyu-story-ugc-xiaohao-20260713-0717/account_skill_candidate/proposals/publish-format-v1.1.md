# 闲鱼故事 UGC 发布呈现与单图生产 v1.1 提案

## 反馈归纳

本次反馈跨 5 条同批生产内容重复出现，属于明确的生产执行偏好：

1. 默认直接生成无占位符的第一人称完整稿，不等待用户先确认真实经历。
2. 同批内容不能共用同一叙事骨架；开头、推进、篇幅、标题句式和结尾必须差异化。
3. 5 条一批至少使用 3 个主方法、3 种开头、3 种结尾、2 个篇幅档和 4 种完整结构签名。
4. 未指定题材的批量生产优先选择实物交易、旧物痕迹、交易反差、退坑转手和短交易奇遇；不主动选择 PPT、技能服务等 `xugc-m04` 方向。
5. 每条内容默认只配 1 张与正文物件一致的生活化图片。
6. 生成补图不在画面内添加“AI 示意图”、水印、标签或其他文字；生成来源留在内部记录，不把补图当成交易证据。
7. 用户可见稿只保留标题、图片、正文和话题；事实边界、内部方法追踪、视觉来源与隐私检查继续内部保留，不混入发布文案。
8. 话题直接接在正文后面，不增加“话题：”标题或独立说明区块。

## 拟修改 `skill/SKILL.md`

在生产流程中新增“用户可见稿与内部包分层”：

```markdown
生产时继续维护事实边界、方法追踪、视觉来源和隐私检查，但这些属于内部结构化包。默认用户可见发布稿只输出：标题 → 单张图片 → 自然分段正文 → 紧随正文的话题。除非用户要求审核信息，不在发布稿中展示“事实边界”“内部方法追踪”“视觉包”等标签。
```

在输入门后新增直接成稿规则：

```markdown
默认直接生成无占位符的第一人称完整成稿，不在写作前等待用户逐项确认，也不添加“虚构”“情景创作”等标签。缺少精确金额、身份、聊天原句、收入或外部结果时，使用不依赖这些数据的一般化写法，不生成伪造截图或平台成绩。
```

在方法路由后新增默认方向偏好：

```markdown
当用户只要求批量生成且未指定题材时，当前默认优先实物相关的 `xugc-m01/m02/m03/m05/m06`。`xugc-m04` 同城服务、手作或技能变现仍保留为正式方法，但只在用户明确要求服务、接单或技能变现方向时进入。用户当次指定优先于此默认偏好。
```

## 拟修改 `skill/references/production.md`

把交付格式拆成两层。

同时新增批次结构差异表：5 条一批至少分配 3 种开头、3 种结尾、3 个主方法、2 个篇幅档和 4 种完整结构签名；不得写完第一条后只替换物件、金额和人物。

### 内部结构化包

继续保留：

- 标题、正文、话题；
- 输入事实与待确认项；
- 主方法与完成证据；
- 图片来源、生成来源、隐私检查和证据边界；
- topic_id、content_id 与账号 Skill 版本。

### 用户可见发布稿

默认格式改为：

```text
【标题】

【单张图片】

【自然分段正文】

#闲鱼 #具体物件 #生活阶段或交易类型
```

执行要求：

- 不显示“标题：”“正文：”“话题：”等说明标签。
- 不显示事实边界、内部方法追踪、视觉模式和隐私检查。
- 话题紧接正文末尾，不另建话题说明区块。
- 批量交付时每条内容独立成块，不在一张联系表中合并多条图片。

## 拟修改 `skill/references/visual.md`

新增“当前默认单图生产偏好”：

```markdown
未提供原图且用户要求补图时，每条内容默认生成 1 张竖版生活化实物图，按 `single_visual` 组织用户可见稿。图片应与正文核心物件一致，保留普通手机拍摄感，不使用棚拍、品牌模板、平台界面、聊天、订单或评价截图。

生成补图不在画面内添加 AI 标识、水印、标题或标签。生成来源只记录在内部视觉清单中，且该图片不得被声明为真实交易证据。用户明确要求多图或提供多张真实证据图时，再按对应视觉模式执行，单图默认不覆盖当次明确要求。
```
