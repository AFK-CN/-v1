# 知识图谱构建与调用规则

## 定位

知识图谱是现有知识库系统层的派生能力，不是第二套知识库。执行入口仍为 `tools.kb.cli`，正式知识、候选知识、原始资料和运行产物的既有边界保持不变。

## 输入边界

- 系统层只读取 `graph_sources.json` 白名单中的入口、路由、规则、配置和工具。
- 正式知识只从 `formal_knowledge_index.json` 获取文件清单，不自行遍历知识目录。
- 候选层只生成汇总节点，只读取候选索引的数量和生成时间，不展开候选条目或正文。
- `数据/`、`00_Inbox/`、`99_Archive/`、`80_Local/`、`20_User/private/`、`00_System/runtime/` 和 `90_Temp/` 默认禁止作为图谱输入。

## 关系可信度

- `deterministic`：目录包含、阶段先后等由结构确定的关系，可信度为 high。
- `explicit`：文档链接、路由配置、输出契约明确声明的关系，可信度为 high 或 medium。
- `inferred`：底层抽取器推断的调用或使用关系，可信度为 low，Web 默认弱显示。

## 五类视图

1. 系统：入口、路由、规则、配置、工具与执行关系。
2. 正式知识：正式文件、章节、来源和领域。
3. 账号：账号中心、方向、方法和证据。
4. 流程：学习阶段、确认门、工具与产出物。
5. 跨层关系：系统如何调用知识、流程如何产生候选和正式知识。

## 查询与回查

图谱查询只用于缩小范围和解释关系。任何需要引用具体事实的回答，必须根据节点的 `source_file` 和 `source_location` 回查原文件。图谱不得直接修改正式知识；发现缺失或错误时，回到原有候选、审核或 proposal 流程。

## 运行约束

- Graphify 仅作为 Python 库调用，不运行其安装器，不修改 `AGENTS.md`，不安装 Git hook，不启动 watcher。
- 构建产物统一写入 `00_System/runtime/graphify/`。
- 初期采用手动全量重建，版本固定为 `graphifyy==0.9.15`。
