# 统一学习卡产出标准

本规则定义所有账号、平台和内容形态共用的深度学习卡契约。系统只规定通用字段、证据边界、完成标准和失败条件，不包含任何账号的具体方向、口吻、模板或内容结论。

机器契约：`00_System/shareable/config/account_learning_card_contract.json`。

单卡生成后必须运行：

```bash
.venv/bin/python -m tools.kb.cli --root . account-learning-validate-card --path "{学习卡路径}"
```

命令返回 `schema=unified_three_layer_v2`、`section_count=12`、`ok=true` 后，才可进入五视角候选提取。历史卡可按兼容模式读取，但不能冒充新统一卡完成状态。

## 一、三层结构

### 1. 证据层

回答“这张卡依据什么、可信到哪里”：

- source_id、原内容链接、账号、平台、方向、批次和状态。
- 主证据、辅助证据、逐字稿/OCR/视觉分析状态。
- 内容形态、场景、关系、表达机制等可复核分类。
- 商业属性、平台活动和广告隔离判断。
- 缺失证据、降级状态和不能确定的内容。

### 2. 内容拆解层

回答“这条内容为什么有效、以后如何复用”：

- 为什么值得学习、核心观点、动态内容结构。
- 发布标题、正文/文案、话题/标签。
- 视频、图文、画面、镜头、节奏、表演或分图结构。
- 原文金句、提炼表达、可复用句式。
- 可复用选题、案例、方法候选和模板。

### 3. 跨卡方法层

回答“哪些单卡候选最终是账号稳定方法”：

- Adler 整体理解。
- 定位、选题、结构、表达、反例五视角候选池。
- V1 跨内容证据、V2 预测指导力、V3 独特性三重验证。
- 完整 RIA++ 方法单元。
- depends_on、contrasts_with、composes_with 关系图。
- 正例、负例、边界例和兄弟方法诱饵压力测试。

单卡不得直接宣布形成稳定方法。单卡只贡献候选和证据，完整方法必须进入跨卡层。

结构机制与表达指纹也属于跨卡结论。统一学习卡仍只记录本条可回查的结构、表达和证据；阶段 1 可以从卡片与源证据派生更深观察，但不得给十二段卡片追加一组强制观察字段，也不得因为某个观察维度缺失而判卡失败。固定结构、表达指纹、反 AI 规则和篇幅完成条件必须经过多卡聚合、反例比较和三重验证后才能成立。

卡片审核状态不等于方法调用状态。即使学习卡状态为 `review_passed`，其中的单卡方法仍不可直接调用；必须先与其他视角候选聚合、通过三重验证和压力测试，再经过现有正式审核流程。

## 二、单卡必需元信息

每张新卡必须包含：

```text
学习卡契约：unified_three_layer_v2
source_id：唯一来源标识
原内容链接：可回查链接
账号：来源账号
平台：来源平台
主方向：本次学习方向
学习批次：批次或 workflow_id
状态：candidate_learned / review_passed / formal_ingested
```

完成标准：字段非空，source_id 与证据文件一致，候选卡不能标成 `formal_ingested`。

## 三、单卡十二段标准

### 1. 证据边界

必须写明：主证据、辅助证据、证据状态。证据状态覆盖逐字稿、OCR、视频、图片、抽帧或视觉复核；缺失项必须显式标注。

失败条件：只写“有证据”但不说明来源；把标题、正文和同一逐字稿重复算成多个独立证据。

### 2. 为什么值得学习

说明本条在观点、结构、表达、表演、视觉、标题或边界判断上的学习价值。指标只能作为辅助，不得只因播放量高而入选。

### 3. 多维分类与商业隔离

至少包含：内容形态、商业属性、隔离判断、分类依据。可按任务增加人物关系、场景、表达机制、视觉类型等维度。

失败条件：广告主导内容进入核心方向；平台活动被当作稳定账号规律；系统规则预设某个账号的分类词。

### 4. 核心观点

至少两条：内容明确表达的观点，以及从证据中可合理归纳的表达机制或判断。不得把标题改写一遍冒充核心观点。

### 5. 内容结构

根据内容形态选择结构，不得统一强套知识口播模板：

- 知识/评论：黄金3秒、观点提出、证据或案例、推演、收尾。
- 剧情/故事：开头设定、核心冲突、升级、转折或笑点、收尾。
- 图文：封面承诺、分图顺序、信息层级、行动建议、收尾互动。

### 6. 发布内容层学习

必须分别学习标题、正文或文案、话题或标签，并说明三者如何共同完成内容承诺。没有显式话题时写明缺失，不得自行补造。

### 7. 视频/图文表现层学习

必须写明媒体类型、分析状态、表现学习：

- 视频关注口播、字幕、镜头、节奏、停顿、表演和场景。
- 图文关注封面、分图角色、顺序、OCR、视觉层级和收藏理由。
- 证据不足时写降级结论，不根据想象补画面。

### 8. 金句与表达素材

强制区分：

- 原文金句：必须能在逐字稿、正文或 OCR 中回查。
- 提炼表达：系统按原意总结，必须标明不是原话。
- 可复用句式：只抽象表达结构，不复制来源内容。

失败条件：把提炼句写成原文；引用无法回查；只列空泛形容词。

### 9. 可复用选题与案例

至少包含一个可复用选题和一个来源案例。复用选题必须换场景或对象，不得只替换关键词。

### 10. 方法候选与可复用方法论

单卡使用候选版 RIA++：

- R：本条原始证据。
- I：初步解释。
- A1：本条已发生案例。
- A2：未来可能触发的内容任务。必须按抽象机制描述，不得直接复述本条可复用选题。
- E：初步执行步骤。
- B：不适用场景、证据局限或反例。

A2 必须包含：

- `触发机制`：新任务出现什么冲突因果、信息差、限制条件或结构需求时调用。
- `适用关系`：来源人物关系只作为已证实案例；说明能否迁移到其他关系。
- `可迁移场景`：来源场景只作为 A1；说明机制成立时可迁移到哪些类型场景。
- `不触发条件`：只命中人物、场景、道具或题材词，但不具备核心机制时不得调用。

调用顺序固定为：先按正式状态、账号、内容形态和主任务方向建立基础范围，再按机制做跨方向扩展，最后用边界排除。方法选择必须在生成前完成；不得因为草稿中偶然出现“情侣”“校园”“影院”或某个道具词，写到一半才临时追加方法。

例如，来源案例发生在某个公共场所，不代表只有该场所才能触发；只要新任务同样需要“观众先获得关键信息、角色延迟发现、末尾完成认知反转”，就可以跨场景调用。反过来，任务只出现相同场所或道具，却没有这套信息差结构时，不得调用。

完成标准：六段齐全，A2 四项齐全，并明确写“候选，待跨卡三重验证”。

### 11. 可复用模板

输出可填空的结构模板，至少包含两个可替换位置和适用边界。人物关系和场景必须写成可替换槽位，不能把来源关系、场景或道具固定成调用前提。模板只能抽象结构，不能复制账号专属故事、身份或事实。

### 12. 证据缺口与候选判断

必须包含：证据缺口、卡片判断、跨卡状态。跨卡状态只能是待验证、支持候选、反驳候选或边界证据；未经三重验证不能写成正式方法。

## 四、跨卡产出标准

跨卡层按 `账号专业学习提取与验证规范.md` 执行，必须产出：

1. `ACCOUNT_OVERVIEW.md/json`：账号整体结构、解释、批判和应用潜力。
2. 五类 `candidates/*.jsonl`：每条都有 id、标题、类型、source_refs、摘要、标签。
3. `candidate_clusters.jsonl`：把五视角观察聚合为方法候选、边界规则或证据门；每条原始候选恰好分配一次。涉及结构或表达的方法候选还要解释固定与可变单元、张力、信任、理解、受益、篇幅完成条件和边界。
4. `verified.jsonl` 与 `rejected.jsonl`：每个机制簇恰好进入一个集合并写明理由。
5. `methods/{id}/METHOD.md` 与 `method.json`：完整 RIA++、触发、步骤、边界和不可调用状态。
6. `METHOD_INDEX.json` 与 `GLOSSARY.md`：方法关系和共享术语。
7. 每个方法的 `test-prompts.json` 与 `test-results.json`：包含提示集哈希、逐案例结果且通过率 100%。
8. `LEARNING_DIGEST.md`、`promotion_manifest.json` 与 `ACCOUNT_PRODUCTION_HANDOFF.json`：候选交付及账号生产规则映射，`callable=false`，不直接写正式知识。

## 五、兼容与迁移

- 历史十段式卡继续作为正式知识或候选证据读取，不批量重写。
- 历史证据型卡继续作为证据读取，不自动视为完成统一学习。
- 新生成卡必须使用 `unified_three_layer_v2`。
- 只有重学、补学或用户明确要求迁移时，才把历史卡转换成统一卡。
