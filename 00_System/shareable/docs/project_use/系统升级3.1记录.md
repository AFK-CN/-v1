# 系统升级 3.1 记录

## 升级目标

在系统 3.0 的知识治理、正式混合检索、账号隔离、视觉来源边界和账号 Skill 防回退机制上，补齐“逐条表达资产提取、拆解、聚合、检索、压测和交付”。本次只优化系统，不执行真实账号学习，不读取账号中心内容，不生成账号资产，也不把账号内容写入系统层。

升级前 Git 基线：`d7871e4b38f34ef6930505615b2a6f165a2939ee`。

## 单一工作流

系统仍只有一套 active 账号学习工作流：原七阶段 ID、顺序和确认门不变，表达资产作为并行链嵌入各阶段，不另建第二套流程。

- 阶段 0：审计证据覆盖，不提取。
- 阶段 1：逐条列出并拆解最多 20 条样本资产。
- 阶段 2：执行检索、溯源、抽象、改编、风险和账号隔离验收。
- 阶段 3：方法可以引用资产，但不能吞并或删除来源资产。
- 阶段 4：聚合钩子、金句、句式与完整结构图谱，建立资产—方法链接。
- 阶段 5：执行检索、改编、原句复制、效果承诺、账号污染与跨媒介错配测试。
- 阶段 6：同时交付机器 JSONL/manifest 与中文可见拆解包，保持候选不可调用。

新任务默认使用升级后的机制。以前保存的任务不会复制为另一套工作流；需要继续时，在原 workflow_id 上经用户确认原地补齐新增产物，阶段记录、旧能力和旧产物都保留。

## 新增表达资产

资产类型包括：

- 钩子：开头、信息差、段落/镜头转场、冲突、证据、反转、情绪和结尾；
- 金句与句式；
- 结构单元与转场；
- 开头动作与结尾动作；
- 痛点、改编骨架、反例和慎用表达。

每条资产记录来源层、内容位置、功能、来源原文、机制拆解、变量、改编骨架、风险、结构可用性、独立效果证据状态、生命周期和门禁证据。发布标题、发布正文、口播、视觉和跨模态协同分别保存，不能互相替代。

## 机器与人工产物

机器产物包括统一 `expression_assets.jsonl`、按类型拆分的 JSONL、来源登记、验收回执、资产—方法链接、压力测试报告和 manifest。

中文可见产物包括：

- `表达资产总览.md`
- `钩子与留存机制图谱.md`
- `金句与句式图谱.md`
- `内容结构完整图谱.md`
- `发布层与视频层协同图谱.md`
- `表达资产使用说明.md`
- `反例与慎用表达.md`
- `单条内容拆解索引.md`

这些产物由同一份通过校验的 JSONL 派生，避免“列表、拆解和检索索引互相不一致”。

## 污染与生成边界

- 系统配置、Skill 和代码只保存通用 schema、类型、状态机、校验和验收规则。
- 系统层不保存账号名、账号原句、source_id、账号方法或账号结论。
- 每个候选包只能包含一个 account_id；禁止跨账号补样本、合并规则或借用验收证据。
- 来源原文只可展示与溯源，永远 `generation_eligible=false`。
- 候选抽象模式也不可直接生产；需跨卡验证、压力测试、用户确认和正式 Skill 提案后才可另行晋升。
- 用户拒绝产物只能进入 `anti_pattern + rejected + validation_only`。
- 结构可用性评分不代表传播效果；单条内容、逐字稿和主观评分不能证明效果。
- 原始资料只读；本次升级不访问 NAS、不处理账号中心、不写正式账号目录。

## 能力保留

系统 3.0 已有的七阶段学习卡、五视角观察、三重验证、RIA++ 方法、视觉来源隔离、发布文案专项、真实验收、压力测试、账号 Skill 候选包、轻量数据源边界和旧能力 ID 防回退机制全部保留。

任何旧能力删除、替换、弃用或语义变化仍必须形成提案、用户确认和回滚记录。表达资产增强只能做能力增量，不能成为删减旧能力的理由。

## 回滚

若验收失败，恢复升级前 Git 基线中的 account-learning v2.9、pipeline 2.9 和 expression contract 3.0。新增候选保持不可调用并保留审计，不删除原始资料、正式知识、账号 Skill、候选资产或历史工作流。

## 验收状态

当前状态由 `00_System/shareable/config/system_version.json` 管理。只有完整单元测试、系统验证、运行时健康检查、系统边界审计、账号污染检查、分发审计、正式检索烟测、单一工作流测试、表达资产交付测试、原文禁生成测试和旧任务原地升级测试全部通过后，3.1 才可从 `validating` 切换为 `active`。
