# 系统升级 3.0 记录

状态：active，完整验收通过

日期：2026-07-19

## 升级目标

本次核心是优化知识库系统。系统层不执行真实账号学习，即不执行新的原始资料账号学习，也不把账号内容写入系统层；经用户确认，对全部注册账号的既有正式学习结果补齐 v2.9 能力继承、候选快照和逐账号验收。账号名称、能力、图片和规则仍只留在对应账号目录。多用户和 Web 界面不在本次范围。

## P0：现有系统收口

- 修复正式账号版本升级后遗留的测试断言漂移。
- 重建 Skill 包、索引和看板等可复现产物。
- 保留用户现有重组变更，不清理、不重置、不覆盖无关文件。

## P1：正式知识混合检索

- 新增 BM25 关键词检索、本地字符 n-gram 哈希向量、严格元数据过滤和轻量重排。
- 只索引 `10_Knowledge/formal/` 中允许的文本类型；排除轻量数据源、候选、原始资料、系统层、用户层、临时层和归档层。
- 返回短摘要、账号/方向/文档角色、分项得分、chunk 哈希和 `path:Lx-Ly` 行号证据坐标。
- 缓存只写 `00_System/runtime/cache/formal_retrieval/`，陈旧时阻断检索并要求显式重建。
- 本地哈希向量只声明模糊相似，不冒充神经语义嵌入。

## P2：表达资产改编

- 吸收的通用资产类型：hook、golden line、opening move、ending move、pain point、anti-pattern、adaptation template。
- 改编为 JSON 契约、独立来源/效果权威清单、真实文件哈希、账号隔离、连续状态迁移、证据坐标、风险标记、小样本门和回滚门。
- 系统层只保存类型、字段和门槛，不保存账号名、账号原句、source_id 或账号结论。
- 账号候选默认 `callable=false`、`method_evidence_eligible=false`、`generation_eligible=false`；结构可用性评分与封闭字段的传播效果证据分开。
- 表达资产 v3.0 接入 proposal 仍等待单独确认，本次不启动表达资产学习。

## P2 补强：账号学习 AI 输出来源隔离

- 经用户明确授权，把 active account-learning 从 v2.7 升级到 v2.8；只修改系统 Skill、通用契约、校验器和测试。
- 只有账号原图可以承担真实性、真实感和后续生成参考权威。
- 用户认可 AI 输出只能用于页间连续性和构图回归；认可不能改变 AI 来源，也不能升格为母版、黄金正例、账号方法或后续生图参考。
- 校准输出与首张生成结果只能作为回归基线，禁止生成结果自举。
- 生图提示词、模型稳定性约束与验收规则分离；为降低生成失败而减少画面复杂度，不能冒充账号内容规律。
- 新流程由代码强制校验来源、允许用途及真实性/母版/方法/生图资格；v2.7 旧候选不批量改写。

## P3：账号 Skill 升级能力保留与污染隔离

- 经用户确认，把 active account-learning 从 v2.8 升级到 v2.9；表达资产 v3.0 提案仍保持待确认，不随本次自动激活。
- 新建或升级账号 Skill 必须生成 `UPGRADE_COMPATIBILITY.json`，保存稳定能力 ID、升级前后集合、新增差集、显式替换/弃用、关键文件哈希和回滚。
- 任一旧能力 ID 未进入新清单时直接阻断；替换或弃用必须保留历史 ID，并绑定用户确认、替代能力和回滚。
- 单账号升级只允许读取同账号 Skill；整体账号升级也必须一账号一清单、逐账号验收，禁止跨账号合并规则、素材、能力或正例。
- 用户认可的多图成套结果必须保存有序页面、连续性母图、直接父关系和文件哈希；同包要求连续性时禁止逐页独立重生。
- 多图回归包只负责连续性和构图回归，不能获得真实性、真实感、食物母版、黄金正例、方法证据或后续生图资格。
- 全部 5 个注册账号均已生成或保留正式兼容清单；4 个旧版本只增加防回退能力并提升补丁版本，1 个已完成 v2.9 的账号保持原版本和专项能力不变。
- 全部 5 个历史候选工作流已迁移到 pipeline v2.9，并同步本账号当前 `SKILL.md`、引用规则、校验器、方法索引和四个账号视图；候选与正式快照必须逐文件哈希一致。
- 系统级 `account-learning-v29-audit` 强制验证一账号一工作流、同账号来源、旧能力零丢失、候选快照一致、跨账号标识泄漏为 0、核心模板碰撞为 0、生成垃圾为 0。
