# 目录架构治理规则

本文件用于解释系统级清洁后的目录治理边界。它不替代 `00_System/shareable/config/layer_map.json`，只说明执行策略。

## 根目录保留项

- `.github/`：工程控制目录，保存工作流、项目元数据或平台配置；不属于知识库垃圾，不进入清理队列。
- `tools/`：当前 Python/CLI 执行入口。虽然在分层映射中逻辑归属 `00_System/shareable/cli`，但物理迁移会影响导入路径、命令入口和测试，必须单独立项。
- `tests/`：当前测试入口。逻辑归属系统层测试，但物理迁移必须和测试发现规则、导入路径一起处理。
- `00_Inbox/`、`数据/`、`99_Archive/`：受保护或历史兼容目录，不默认展开、不默认删除。

## 可以直接清理的垃圾

- `.DS_Store`
- `__pycache__/`
- `*.pyc`

清理时不得进入 `.git/` 或 `.venv/` 做仓库任务级清理。

## 目录迁移原则

- `layer_map.json` 中的 `legacy_mapping` 是逻辑归属和渐进迁移目标，不等于当前必须移动。
- 移动物理目录前必须先有迁移计划、导入路径兼容方案、测试发现方案和回滚方案。
- 原始资料、正式知识、候选资产、历史证据和 runtime 报告不因“瘦身”直接删除。

## 验收口径

- `plan-reorg` 不应把 `.github/` 标成 `manual_review`。
- 根目录没有 `delete_candidate` 时，说明当前没有可直接删除的根目录垃圾。
- 物理迁移未完成不等于系统污染，只要调用入口、索引、schema 和验证器明确边界即可。
