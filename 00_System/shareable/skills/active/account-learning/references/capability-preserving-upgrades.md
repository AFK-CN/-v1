# 账号 Skill 能力保留与升级隔离

本规则只定义通用升级机制，不保存任何账号名称、内容规律、素材或专属能力。账号自己的能力清单只能写入该账号候选或正式 Skill。

## 升级前后清单

每个新建或升级候选必须生成 `UPGRADE_COMPATIBILITY.json`：

1. 为可调用能力分配稳定 `capability_id`；同一能力改写措辞、文件或实现时不得换 ID 逃避比较。
2. `previous_capability_ids` 保存升级前完整清单；`capabilities` 保存升级后完整清单。前者每一项都必须仍在后者中。
3. 新能力只进入 `new_capability_ids`，且必须等于升级后清单减去升级前清单的真实差集。
4. `active` 表示继续可用；`replaced` 或 `deprecated` 仍保留历史记录，并必须绑定用户确认、替代能力和回滚。候选阶段只能提出变更，不能自行生效。
5. 关键 Skill 文件保存 SHA-256 快照。任何文件变化都必须更新兼容清单并重新验证，避免只改文本却不记录升级。

## 单账号与整体升级隔离

- 一个兼容清单只允许一个 `account_skill_id`。
- 能力来源文件和账号专属确认提案必须位于同一账号 Skill 内；确认提案必须声明同一 `skill_name`。系统共享提案目录只允许通用机制提案，不得存放账号提案正文。
- 禁止绝对路径、NAS 路径、其它账号目录、跨账号能力合并和跨账号素材补正例。
- 整体升级只是对多个单账号清单逐个运行同一门禁，不产生公共账号能力池。
- 系统层只能保存字段、状态、比较算法和错误码，不保存账号能力正文。

## 多图连续性

用户认可的一组成图若用于回归，必须作为一个有序包保存：

- `continuity_mother_asset_id`；
- 完整页面顺序与页面角色；
- 每页直接父关系；
- 不变量、可变字段和局部编辑策略；
- 文件哈希与成套数量。

同一内容包要求连续性时，独立文件不等于逐页独立重生。优先从母图做裁切、标注或局部编辑；若必须整图重生，应新建内容包并重新校准，不能把旧包的页面连续性声明为已继承。

用户认可不能改变 AI 来源。该有序包只允许 `page_continuity_regression` 和 `composition_regression`，真实性、真实感、母版、黄金正例、方法证据和生成参考资格必须全部为 `false`。

## 完成门

候选阶段、正式写入、注册表同步、整体账号迁移和发布前系统验收都必须运行兼容校验。任一旧能力丢失、变更无用户确认、来源越过账号边界、多图包缺母图/顺序/父关系，或 AI 回归包获得真实感权威时，升级失败并回滚到上一个已验证版本。

历史工作流不得因为旧版兼容逻辑而被视为已补齐。整体升级必须依次通过：

1. `account-skills-v29-audit`：正式账号 Skill 能力清单审计；
2. `account-skills-v29-upgrade --all --user-confirmed`：经用户确认后逐账号生成正式兼容清单；
3. `account-learning-migrate --all --force`：只从同账号正式 Skill 回填历史阶段 6 快照；
4. `account-learning-v29-audit`：核对注册账号、工作流、版本、发布文案、校验器、方法索引、延期证据隔离和垃圾文件。

任一注册账号没有且仅有一个 v2.9 工作流，或延期证据未从可调用能力中隔离，整体验收直接失败。
