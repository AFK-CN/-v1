# 项目长期规则

来源：历史会话沉淀、当前项目结构与已验证系统规则。  
用途：作为当前知识库项目内所有会话通用的长期规则，不写入全局记忆。

## 1. 默认读取与索引边界

- 默认读取必须走轻量入口：`knowledge_index_summary.md`、`task_entry_index.md`、`account_knowledge_index.json/md`。
- `knowledge_index.json` 是全量机器索引，只给脚本、全量审计或用户明确要求时使用。
- `raw_blocked_index.json` 只表达默认禁止读取边界，不展开 `数据/`、`00_Inbox/`、`99_Archive/` 内容。
- 索引、路由、验证器和测试要同步更新；不能只改文档或只改代码。

## 2. 系统层、知识层、用户层边界

- 系统底座放在 `00_System/shareable/`，运行状态放在 `00_System/runtime/`。
- 可分享系统不得混入本机路径、账号、密钥、NAS 地址或运行态。
- 用户可同步内容放在 `20_User/syncable/`，本机私有内容放在 `20_User/private/` 或 `80_Local/`。
- 候选资产属于知识层 candidates，不放入临时层；正式知识与候选证据必须区分。
- Skill 属于系统层，active/proposals/history 要分开；active 修改必须先走 proposal。

## 3. 任务执行偏好

- 复杂任务先规划，再执行；如果用户明确要求直接解决，路径清楚时不要把问题推给新会话。
- 批量机械工作应交给脚本完成，Codex 负责启动、验收和异常审核。
- 不要默认扫描原始数据目录；优先读取索引、manifest、status、报告、注册表、验证输出。
- 长任务不要靠聊天陪跑；应写任务文件、日志、状态和心跳。
- 系统结构或流程变更后，必须跑测试、`validate-system`、索引重建和旧路径残留检查。

## 4. 记忆沉淀规则

- 记忆系统是系统能力，但具体记忆按层存放。
- 系统可以自动判断是否生成记忆候选，但不是每次结束都生成。
- 只有用户纠正规则、长期偏好、可复用流程、已验证修复、智能体边界变化等才生成候选。
- 自动候选只进入 `00_System/runtime/memory/pending_session_extracts.jsonl`，不能直接写长期记忆。
- 低价值结束语、一次性过程、未验证判断和用户明确说不用记的内容不生成候选。

## 5. 智能体登记与登录边界

- 当前智能体默认是 `logical_role`，是同一次 AI 调用中的逻辑职责，不是独立账号或权限边界。
- 智能体功能、ID、能力、入口、记忆范围放在 `20_User/syncable/agents/agent_registry.md`。
- 登录状态、账号标签、凭证位置提示只放 `20_User/private/agents/`，不写真实凭证。
- 智能体能力边界由系统路由、schema、索引、输出契约和验证器共同约束。
