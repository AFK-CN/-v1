# 输出契约

用途：固定每类知识库任务必须输出什么，避免“能生成但不可追溯”。

机器可读配置在：

```text
14_KB_System/config/output_contracts.json
```

## 通用要求

- 所有内容生产都要说明命中的路由和读取的知识层级。
- 固定高级入口缺少最低信息时，先反问最多 3 个关键问题；只缺可选信息时，说明默认值后再执行。
- 涉及账号、对标内容、案例时，必须保留 `source_id`、原链接、来源层级和证据边界。
- 候选资产、粗扫线索、正式单卡、逐字稿必须分层标注。
- 内容生成结果不能直接反写正式知识。
- 可沉淀的新规则只能进入 proposal，不能直接覆盖 active Skill。

## 关键任务契约

### 出选题

必须包含：选题标题、对应方法论、受众痛点、钩子角度、核心观点、对标知识库内容、原链接或证据来源、来源层级、证据边界。

### 写文案/口播

必须包含：黄金3s、完整文案、互动收尾、对标知识库内容、source_id、原链接、来源层级、证据边界。

### 账号学习

必须包含：方向统计、Top 内容清单、深度学习卡、候选学习卡、审核清单、入库建议、不能入库或需补证据内容。

### 复盘

必须包含：有效方法、失效方法、异常内容、下周动作、是否需要生成 Skill proposal。

### Skill 沉淀

必须包含：适用范围、触发条件、证据、拟变更规则、风险、验证用例、回滚方式。

### 其他项目调用

必须包含：调用入口、命中路由、读取层级、允许使用范围、禁止使用范围、正式知识来源、候选证据状态、下一步调用建议。

禁止：默认读取原始数据目录、默认读取未经审核候选资产、把项目外调用变成全库递归搜索、把未确认 proposal 当成 active 规则。

### 系统审计

必须包含：入口状态、active Skill、待确认 proposal、候选待审核、账号中心状态、最近学习状态、验证结果、建议下一步动作。
