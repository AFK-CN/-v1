# 知识库用户操作台

这是给普通使用者看的入口。你可以用两种方式调用：

1. 自然语言入口：`@知识库 + 你的需求`
2. 固定高级入口：`我要出选题 / 我要写文案 / 我要复盘 / 我要入库 / 我要查账号 / 我要学习账号 / 我要看状态 + 具体需求`

固定高级入口是通用入口，不绑定任何账号。比如：

```text
@知识库 + 你的需求
```

```text
我要出选题 按照{账号/风格}帮我出 2 个{方向}选题
```

如果当前界面不识别中文入口，使用兼容入口：

```text
knowledge-base + 你的需求
```

## 固定高级入口

### 1. 出选题

```text
我要出选题 按照{账号/风格/方向}帮我出{数量}个{平台/主题}选题
```

示例：

```text
我要出选题 按照{账号/风格}帮我出 2 个{方向}选题
```

### 2. 写文案/口播

```text
我要写文案 把这个选题写成{平台/形式}，按{账号/风格}输出{字段要求}
```

示例：

```text
我要写文案 把这个选题写成抖音口播，输出黄金3s、完整文案、互动收尾和证据来源
```

### 3. 复盘

```text
我要复盘 复盘这份{截图/表格/数据/反馈}，告诉我有效方法、失效方法、下周动作
```

### 4. 入库

```text
我要入库 处理这份{JSON/截图/表格/视频资料}，先清洗和生成候选，不要直接写正式知识
```

### 5. 查账号

```text
我要查账号 查一下{账号名}目前有哪些方向、正式知识、候选内容和可用于创作的证据
```

### 6. 学习账号

```text
我要学习账号 学习{账号名/资料范围}的新内容，先做粗扫和候选学习卡，不要直接写入正式知识库
```

### 7. Skill 沉淀

```text
我要沉淀规则 把我刚刚反复纠正的规则整理成 Skill proposal，先不要改 active Skill
```

### 8. 运行状态

```text
我要看状态 看一下当前运行状态，告诉我入口、active Skill、待确认 proposal、候选待审核、账号中心、最近学习状态和下一步建议
```

## 需求不清晰时先反问

如果用户只说“我要出选题”“我要写文案”“我要复盘”这类不完整需求，不要直接瞎生成。先最多问 3 个关键问题。

### 出选题缺信息时

优先问：

- 你要哪个方向或主题？
- 你要哪个平台或内容形式？
- 你要几个选题？是否指定账号/风格？

### 写文案缺信息时

优先问：

- 文案基于哪个选题或材料？
- 输出平台和形式是什么？
- 是否指定账号/风格和字数？

### 复盘缺信息时

优先问：

- 复盘对象是截图、表格、JSON 还是人工反馈？
- 时间范围和平台是什么？
- 你想要周复盘、单条内容复盘，还是方法论复盘？

### 入库缺信息时

优先问：

- 要处理的资料在哪里或是哪一类？
- 是否只生成候选和报告？
- 是否允许进入正式入库审核？

### 查账号缺信息时

优先问：

- 要查哪个账号？
- 想查正式知识、候选内容、方向结构，还是可创作证据？

## 默认补全规则

只有在用户已经给出足够信息时，才可以直接执行。最低要求：

| 任务 | 最少需要的信息 |
|---|---|
| 出选题 | 主题/方向 + 数量；平台和账号可选 |
| 写文案 | 选题/材料 + 输出形式；平台和账号可选 |
| 复盘 | 数据来源/截图/表格 + 复盘目标 |
| 入库 | 资料类型/路径 + 是否只生成候选 |
| 查账号 | 账号名 + 查询目标 |

如果缺少最低信息，先反问；如果只是缺少可选信息，可以采用默认值并在输出开头说明。

## 输出必须说明

每次调用知识库后，输出里应该说明：

- 本次命中的任务路由。
- 本次读取的知识层级。
- 是否使用了账号中心、方向方法论、粗扫、单卡或逐字稿。
- 哪些内容是正式知识，哪些只是候选证据。
- 如果需要沉淀规则，应该进入哪个 proposal。
- 如果是运行状态任务，应该读取 `14_KB_System/runtime/reports/latest_kb_dashboard.md` 或运行 dashboard 命令。

## 使用边界

- 默认不全盘扫库。
- 默认不读取 `数据/`、`00_Inbox/`、`99_Archive/`。
- 候选资产不是正式知识。
- 内容生成结果不能直接反写正式知识。
- active Skill 修改必须先进入 proposal，并由用户确认。
