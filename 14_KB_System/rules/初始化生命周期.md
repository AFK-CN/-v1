# 知识库 Initialization Lifecycle

## 初始化触发条件

新机器首次使用、runtime/manifest/健康凭证缺失、schema 不匹配、旧目录迁移未执行或用户显式要求时，执行 `kb init`。

## 初始化职责

`kb init` 在 KB root 共享的 maintenance lock 内幂等执行：

1. 创建 `runtime/{state,cache,reports,logs,tasks,locks,quarantine}`。
2. 写 root ID、schema、生成器和迁移版本 manifest。
3. 迁移旧 state、assets、latest reports、logs 和可执行 tasks。
4. 将没有 `status.json` 的长期计划迁移到 `14_KB_System/plans/`。
5. 隔离损坏 runtime JSON。
6. 重建索引、注册表和 dashboard 等可再生产物。
7. 签发 Asia/Shanghai 当日共享健康凭证。

迁移前使用：

```bash
.venv/bin/python -m tools.kb.cli --root . init --dry-run
```

## 初始化边界

init 不读取 `数据/`、`00_Inbox/`，不修改正式知识或 active Skill，不恢复、重新排队或重跑任何任务。

## 日常 Health Gate

初始化后，日常调用只执行 `health-gate`。它不是 preflight，禁止遍历正式知识文件或计算完整知识指纹。

凭证存放在 `00_System/runtime/state/health_credential.json`，因此同一 KB root 当天跨项目共享。

`health-gate` 只读取 manifest、共享凭证、dirty generation、maintenance lock，并对固定控制文件做元数据指纹比较，不展开目录。当天、schema、root ID、控制指纹和 dirty generation 都未变化时直接返回 `healthy`；跨日或指纹/dirty generation 变化时返回 `requires_doctor`；runtime、凭证、目录结构或迁移版本缺失时返回 `requires_init`。

## Doctor、Repair 与锁

- init、doctor、repair 共用 `runtime/locks/maintenance.lock/`。
- 同机 PID 已不存在且 heartbeat 超时后，才允许回收旧锁。
- repair 只能重建可再生产物和将失联 running task 标记为 stale。
- repair 不能恢复、重新排队或执行任何任务命令。
