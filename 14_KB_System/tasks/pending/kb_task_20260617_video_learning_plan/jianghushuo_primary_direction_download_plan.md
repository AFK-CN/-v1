## 4. 提交前生成严格目标清单

代码必须先输出：

`01_Case_Cleaning/video_learning/plans/jianghushuo_primary_top10.json`

每条记录至少包含：

```json
{
  "source_id": "视频唯一 ID",
  "account_name": "姜胡说",
  "primary_direction": "13 个方向之一",
  "secondary_directions": ["辅助方向"],
  "direction_rank": 1,
  "heat_score": 0,
  "selection_reason": "为什么该视频以此方向为主",
  "material_status": "complete|metadata_only|failed|missing",
  "needs_download": true
}
```

生成规则：

1. `account_name` 必须精确等于 `姜胡说`。
2. 每个 `source_id` 只能出现一次。
3. 每条视频必须且只能有一个 `primary_direction`。
4. 先判断视频核心问题和主要结论，再分配主方向；不能按关键词字典顺序决定。
5. 每个方向按热度、内容完整度、方法论价值综合排序，保留 Top10。
6. 13 个方向最多形成 130 个唯一 `source_id`；若某方向不足 10 条，按实际数量形成目标清单，不用其他方向补位。
7. 当前已有完整视频和逐字稿的目标项标记为 `complete`，不重复下载。
8. `metadata_only`、`failed`、`missing` 全部标记为 `needs_download: true`。
9. 生成下载队列前，再按本地非空 `source.mp4` 和 `transcript.srt` 校验一次；校验通过的条目强制改为 `needs_download: false`。

如果某个方向在姜胡说全部内容中不足 10 条，必须在报告中明确写出实际数量，禁止用其他方向的视频凑数。

## 6. 执行方式

本次不是把所有视频同时并发下载，而是“一次提交全部任务、后台顺序执行”。这样既不需要人工分批启动，也能减少抖音链接超时、转写抢占资源和日志混乱。

执行顺序：

1. 生成并校验最多 130 条严格主方向目标清单。
2. 复用目标清单中已有的完整素材。
3. 生成所有未完成项目的唯一下载队列。
4. 启动一次后台下载任务，顺序完成下载、音频提取、转写和抽帧。
5. 单条失败记录错误后继续下一条。
6. 全队列消费结束后生成完成度报告。
